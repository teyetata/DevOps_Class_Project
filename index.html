PENJELASAN DEVOPS

// Apa itu DevOps?

DevOps adalah kombinasi dari filosofi budaya, penerapan, dan peralatan yang meningkatkan kemampuan organisasi untuk memberikan aplikasi dalam kecepatan tinggi. Di bawah model ini, tim pengembangan (Dev) dan pengoperasian (Ops) tidak lagi terisolasi, melainkan digabungkan sepanjang siklus hidup aplikasi. Budaya ini membantu pengumpulan kebutuhan sistem hingga penerapan menjadi lebih cepat, handal, dan efektif. Perusahaan seperti PayPal, Facebook, dan Netflix sukses mempercepat pengembangan dari berbulan-bulan menjadi hitungan minggu/hari menggunakan DevOps.

// DEVOPS TOOLCHAIN

1 PLAN

Perencanaan memperhitungkan metrik produksi dan metrik bisnis. Proses ini membutuhkan perencanaan yang agile dan transparan, seringkali dikelola menggunakan pendekatan klasifikasi tugas/fitur pada issue boards seperti JIRA atau GitHub Issues.

2 CREATE

Pengembangan perangkat lunak yang dilakukan secara kolaboratif. Semua source code dan konfigurasi dikendalikan secara aman menggunakan Git repositories (seperti GitHub, GitLab, Bitbucket) untuk memfasilitasi komunikasi dan transparansi.

3 VERIFY

Proses pengujian source code secara manual antar developer maupun otomatis (dari analisis statis hingga skenario fungsionalitas). Pada Git, sekumpulan komit digrup menjadi pull-requests yang siap diverifikasi oleh developer lain.

4 PACKAGE

Tahap terakhir dari tim pengembang di mana source code yang diverifikasi digabung dan dikemas menjadi aplikasi siap pakai untuk end-user. Bisa di-packaging untuk sistem lokal atau container registries (seperti Docker Hub).

5 RELEASE

Tahap awal tim operasi, yaitu instalasi aplikasi ke sistem pengguna. Distribusi aplikasi sangat mempertimbangkan downtime yang diizinkan, target lokasi/perangkat pengguna, dan biaya infrastruktur.

6 CONFIGURE

Manajemen konfigurasi waktu proses (runtime) dan infrastruktur sistem. Konfigurasi dibuat dan diatur sebagai kode (as code) di dalam Git repositories agar tim secara transparan mengetahui kebutuhan sistem.

7 MONITOR

Tahap terakhir yang paling kritis untuk memberikan feedback metrik produksi dan bisnis kembali ke tahap Planning. Terdiri dari proses logging, error tracking, dan cluster monitoring untuk menyelesaikan masalah secara proaktif.
